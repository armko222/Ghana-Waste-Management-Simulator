Capacity Guard: Initialized with a fixed capacity. Pushing onto a full stack triggers a controlled IllegalStateException("Stack overflow") rather than an unhandled array index exception.  LIFO Order: Elements are pushed onto elements[++top] and popped from elements[top--], ensuring $O(1)$ access for both push and pop.  Top-Down Inspection: Provides a getRecentActions() traversal method that walks backwards from top down to 0. This exposes the audit trail in reverse chronological order without mutating or popping items from the stack.  2. Database Persistence & Audit Log ServiceEvery operational action (e.g., dispatching resources, status updates, bulk imports) generates an AuditEvent that is pushed onto ArrayStack for instant in-memory retrieval and persisted via AuditEventRepository into the auditevent SQL table.  Nullable Field Handling: AuditEvent.relatedRequestId is optional (e.g., system-wide IMPORT actions do not tie to a specific request). The repository uses Types.VARCHAR null checks inside JDBC PreparedStatement execution to ensure safe database inserts.  Timestamp Precision: Timestamps are accurately converted between java.time.LocalDateTime and java.sql.Timestamp during repository save, findById, and findAll calls.  4. Design DecisionsArray-Backed Stack vs. Linked List: An array implementation was chosen for memory locality, constant $O(1)$ stack operations, and explicit capacity boundaries suitable for auditing bounded recent actions.  Controlled Overflow/Underflow: Rather than letting array index boundaries throw raw language errors, isFull() and isEmpty() explicit checks throw IllegalStateException with clear error messages ("Stack overflow" and "Stack underflow").  No Built-in Java Collections for Core Logic: As mandated by course rules, ArrayStack uses raw array storage and custom index management. AuditEventRepository uses standard JDBC (PreparedStatement, ResultSet), which is explicitly permitted for database layer tasks (Handbook Section 8.ii).  5. Genuine Use in the SystemArrayStack powers the system-wide operational audit log. Whenever Role 13 (Dispatch) or Role 1 (Domain/Import) executes a meaningful action (such as assigning a truck or updating request states), an AuditEvent is generated. The stack provides instant, top-down access to the most recent system history for console review and operational reports (Role 14).  6.
